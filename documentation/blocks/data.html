2. Data

Reading ERA5 fields and station records, and turning them into predictors and a target

The data block of the NLSA Python toolkit: data specifications for ERA5 reanalysis and 14th Weather Squadron station records, time settings, climatology removal, smoothing and standardization, spatial sampling, file requirements, and the Lorenz 63 test data.

Every experiment has predictors and a target. The predictors (called covariates in the code, class Covariate) describe the state of the system at the time a forecast is made. The target (response, class Response) is the quantity to forecast, or to verify against.

Both are made of data specifications: an era5.DataSpecs for a reanalysis field or a ws44.DataSpecs for station records. A data specification says which variables to read, over which domain or at which stations, for which period, from which files, and how to remove the climatology and standardize. For example, the predictors of the Niño 3.4 forecasts:

sst_field = era5.DataSpecs(
    vars=[era5.Var.SST],                                   # sea surface temperature
    domain=era5.nino34_domain(step_lon=4, step_lat=4),     # every 4th grid point
    time=Time(date_range=("1940-01-01", "2019-12-31"), sampling="monthly",
              custom_climatology_date_range=("1940-01-01", "2019-12-31")),
    io=era5.IO(input_path="/storage/data/era5/monthly_1940-2025_nc", file_format="nc"),
    climatology=Climatology(remove=False, standardize=True),
)
predictors = Covariate(specs=(sst_field,))

Processing steps

clim.extract_data_arrays(data_pars) reads the predictors and the target of a DataPars object and returns them as arrays. For each ERA5 data specification, clim.read_gridded_dataset does the following, in this order:

  1. Open the files. All files in the folder io.input_path with the extension io.file_format are opened together as one data set, sorted by latitude, and cut to the domain.
  2. Spatial sampling. Grid points are kept, thinned, averaged in blocks or averaged over the domain, as set by Domain.sampling (see below).
  3. Climatology. If Climatology.remove is set, the mean of each calendar month (monthly data) or of each day of the year (daily data) over the climatology period is subtracted.
  4. Smoothing. If Time.rolling_window is set, a running mean over that many samples is applied.
  5. Standardization. If Climatology.standardize is set, the data are centred and scaled with statistics from the climatology period (see Standardization).
  6. Dates. The period Time.date_range is selected.

The arrays are then assembled: all grid points of all variables become the columns of one array, with one row per time; columns with any missing value are dropped (for example land points of a sea surface temperature field); and the arrays of the different data specifications of the predictors are placed side by side. If DataPars.velocity_covariate is set, the rate of change of every column is computed with a central finite difference and stored alongside (see Delay embedding).

TipThe climatology period comes from the training data

Steps 3–5 use the climatology period, and the dates are selected only at the end. So the climatology period can lie outside the date range, and the test data can (and should) use the climatology of the training period: give both the same custom_climatology_date_range. The files must then cover both the dates and the climatology period.

Time settings

Time (nlsa_models.climate, defined in src/nlsa_models/climate.py)
Option Type or values Default Description
date_range tuple[str, str] required First and last date ("YYYY-MM-DD") of the data. For training data this is the training period, for test data the test period.
sampling "monthly" or "daily" required Time sampling: "monthly" or "daily".
rolling_window int or None None Length, in samples, of a running mean applied after the climatology is removed. None means no smoothing.
rolling_mode "forward" or "backward" or "center" "center" Alignment of the running-mean window: "center" (centred), "backward" (the current and previous samples) or "forward" (the current and following samples).
custom_climatology_date_range tuple[str, str] or None None Period used to compute the climatology and the standardization statistics. If None, date_range is used. Set it to the training period for both training and test data, so that test anomalies use the training climatology.

The running mean uses the samples that are available near the ends of the record (min_periods=1), so the first and last values are averages over fewer samples. One exception: for ERA5 data with rolling_mode="forward", the last rolling_window − 1 dates of the files get no value, so the files must extend at least that far beyond the end of date_range.

Climatology and standardization

Climatology (nlsa_models.climate, defined in src/nlsa_models/climate.py)
Option Type or values Default Description
remove bool False Subtract the mean annual cycle (the average for each calendar month, or each day of the year for daily data) computed over the climatology period.
standardize bool False Rescale the data using statistics from the climatology period (see Standardization above).

Standardization

Standardization puts the predictors on a common scale. The mean is taken over the climatology period, separately at each grid point (after any climatology removal and smoothing). The scaling depends on the data:

Data Scaling
ERA5, "pointwise" sampling Each variable is divided by the square root of its total variance, summed over all grid points and averaged over time. The field as a whole has unit variance, and the relative amplitudes of the grid points are kept.
ERA5, any other sampling Each grid point or average is divided by its own standard deviation.
Station records Each variable of each station is scaled to zero mean and unit variance.

For a pointwise field \(x(s, t)\) at grid points \(s\), with means \(\bar x(s)\) over the climatology period of \(T_c\) samples,

\[ \tilde x(s, t) = \frac{x(s, t) - \bar x(s)}{\Big[\frac{1}{T_c} \sum_{t} \sum_{s'} \big(x(s', t) - \bar x(s')\big)^2\Big]^{1/2}}. \]

This matters when predictors are combined. A pointwise ERA5 field contributes one unit of variance per variable however many grid points it has, while each station variable, and each grid point of a coarsened field, contributes one unit. Since the kernel compares predictors through their total distance, these weights decide how much each block of predictors counts.

ERA5 reanalysis

Domain and spatial sampling

Domain (nlsa_models.era5, defined in src/nlsa_models/era5.py)
Option Type or values Default Description
sampling "pointwise" or "coarsened" or "area_averaged" or "meridionally_averaged" or "zonally_averaged" required How grid points are used: "pointwise", "coarsened", "area_averaged", "meridionally_averaged" or "zonally_averaged" (see Spatial sampling).
min_lon float or None None Western edge of the domain, in degrees east (0–360).
max_lon float or None None Eastern edge of the domain, in degrees east (0–360).
min_lat float or None None Southern edge of the domain, in degrees north.
max_lat float or None None Northern edge of the domain, in degrees north.
step_lon int or None None Step in grid points along longitude: keep every step_lon-th point ("pointwise") or average blocks of step_lon points ("coarsened").
step_lat int or None None Step in grid points along latitude, as for step_lon.
Spatial sampling options (era5.Domain.sampling)
sampling Result Role of step_lon, step_lat
"pointwise" The field at every grid point Keep every step_lon-th longitude and step_lat-th latitude; with ERA5’s 0.25° grid, 4 gives a 1° grid.
"coarsened" Averages over blocks of grid points Block size; at least one step must be given.
"area_averaged" One value per time: the average over the domain Not used.
"meridionally_averaged" A profile in longitude: the average over latitude If step_lon is given, blocks of step_lon longitudes are averaged first.
"zonally_averaged" A profile in latitude: the average over longitude No effect on the result. (The code coarsens longitude by step_lat before averaging over all longitudes.)

Averages are plain means over grid points, not weighted by the area of the grid cells. This makes little difference near the equator but gives more weight to high latitudes in large domains. Domains are cut with min_lon < max_lon in degrees east from 0 to 360, so a domain cannot cross the 0° meridian.

Three domains are predefined; all accept the sampling, step_lon and step_lat arguments:

Predefined domains in nlsa_models.era5
Function Longitudes Latitudes Used for
era5.nino34_domain() 190°E–240°E (170°W–120°W) 5°S–5°N Niño 3.4 predictors and index
era5.indo_pacific_domain() 28°E–290°E 60°S–20°N Indo-Pacific SST for Koopman modes
era5.global_domain() 0°–360°E 90°S–90°N Spatial patterns (projections)

For other regions, create the domain directly, for example the MJO target box: era5.Domain(sampling="area_averaged", min_lon=120, max_lon=150, min_lat=-5, max_lat=5).

Files

IO (nlsa_models.era5, defined in src/nlsa_models/era5.py)
Option Type or values Default Description
input_path str or Path or None None Folder with the ERA5 files. All files with the chosen extension in the folder are opened together as one data set.
file_format "grib" or "nc" "nc" File format: "nc" (NetCDF) or "grib".

The code expects:

  • One data set per folder. Every file with the given extension in the folder is opened, and the files are combined along time.

  • Coordinates named time, latitude and longitude, with longitudes from 0° to 360°. ERA5 NetCDF files from the current Copernicus Climate Data Store name the time coordinate valid_time instead; rename it once after downloading:

    import xarray as xr
ds = xr.open_dataset("era5_sst_monthly.nc")
ds = ds.rename({"valid_time": "time"}).drop_vars(["expver", "number"], errors="ignore")
ds.to_netcdf("era5_sst_monthly_time.nc")

  • One value per month or per day, without gaps. The number of samples is computed from the dates, so missing months or days would misalign the data.

  • Coverage of both the date range and the climatology period.

GRIB files (file_format="grib") are read with cfgrib, which is installed with the toolkit.

Station records

The station records of the U.S. Air Force 14th Weather Squadron are read by nlsa_models.ws44, which has two sets of classes: one for the stations of the southwestern United States and the western Pacific, and one (HighLat…) for Pituffik Space Base in Greenland, whose records come in a different format. For each station and variable, the reader fills missing days by linear interpolation (and prints how many were filled), averages to months if sampling="monthly", then removes the climatology, smooths, standardizes and selects the dates, as for ERA5 data.

Lorenz 63

For the Lorenz 63 examples the data are not read from files but simulated: nlsa_models.lorenz63 integrates the Lorenz 63 equations with the standard parameters (σ = 10, ρ = 28, β = 8/3) with an adaptive Runge–Kutta solver (Diffrax), discards a spin-up period, and samples the trajectory at intervals dt.
